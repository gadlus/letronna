# Changelog

Every change to Letronna — the app, the terminal, on Windows, macOS and Linux —
by version, newest first. One version number covers all of them.

Versions follow [semantic versioning](https://semver.org): `0.x` until the first
stable release, `-alpha.N` / `-beta.N` while it is early. Changes gather under
**Unreleased** and become a version when it is tagged (`vX.Y.Z`), which builds
the release for every platform. Each line starts with where it applies:
**App**, **Terminal**, **Windows**, **macOS**, **Linux**, or **All**.

This file is also the App tab of https://letronna.ai/changelog.

## [Unreleased]

### Added
- **Terminal** — `letronna -p --output json` and the result line of `--output stream-json` say where the run's time went, under `timing`: its requests to the model and the seconds they took, how long its replies took to begin (how many began, the seconds added up and the slowest), the seconds spent waiting for a place on the provider, its tool calls and the seconds they took, and under `checks_seconds` the seconds of the checks Letronna makes itself between replies (the reviews it starts and waits for, a tester's tests run against the work, a second attempt, the project's tests run as they were), with the run's figures for its helpers under `helpers` when any started. Before, a result gave only the seconds the whole run took, so a slow provider could not be told from slow tools.
- **Terminal** — `LETRONNA_DISPOSABLE_FILES=1`, beside `LETRONNA_DISPOSABLE=1`, declares a machine's files throwaway too, as a benchmark's or a CI job's task folder is. A run nobody watches in Bypass that has read a web page, a document or other words someone else wrote then still deletes, writes over and moves files it did not make, and writes outside the project; without it those wait for a yes nobody is there to give. Nothing that sends data off the machine is let through by it, a line that deletes and then sends is held as one that sends, and a deny rule on the tool still holds. Letronna Cloud does not set it. On Terminal-Bench 2.0 the hold cost three tasks outright, where moving the task's inputs or filling in a file it was given was the task, and refused calls in six more failed trials. The Harbor and OpenHuman adapters set it.
- **All** — `LETRONNA_PARALLEL_READ_COMMANDS=on`, or the `parallel_read_commands` setting, lets a run nobody watches run at once the commands of one reply that only read, such as `ls`, `git log` and `cat`, as its file reads run, up to eight together; one of them failing no longer leaves the rest of the reply unrun. Off until paired runs show it sound. `--dump-config` says which experiments are on.
- **All** — `LETRONNA_DUMP_STREAMS=<folder>` keeps each request's body and every line of its reply's stream there, one `.sse` file a request, as they were sent and as they came. When tool calls arrive with no arguments, or with another call's, nothing kept said whether the provider sent them so or Letronna put them together wrongly: on Terminal-Bench 2.0 one model's calls arrived empty in 62 of the 264 replies where it made several at once, and the run's review could blame neither side. The files hold all the model was sent but no header, so no key, and nothing is written unless the variable is set. The Harbor adapter's `streams` option sets it and keeps the files with the trial's logs.
- **All** — A run nobody watches whose request reads as a specification has its work tested from the request alone. A helper that never sees the work, the tester, starts with the run and writes tests from the request's words; when the run says it is done, Letronna runs them against its work in a copy of the project, with the set-up the run's and the tester's own commands needed, and sends the run back with what failed, up to twice. The run's first complete version is kept as a referee: where its work fails tests that version passed, it is told what it changed since. Where the work still fails the tester's own tests, a second helper makes the change again from scratch in the project as it was, and its work takes the first's place only when it passes tests that the first, and the project as it was, do not.
- **All** — A run nobody watches is sent back once for a test the project already had that its change broke, found by running the test on the project as it was. The cases the run weighed and set aside in its own words are given to its reviewers and its tester, without its reasons, each for a row of its own.

### Changed
- **All** — A helper of a run nobody watches is sent the tools its session's own run is, less only those it could not call either, where it was sent every tool, ask_user and memory among them, each refused at the call. Its requests now begin as its session's do, so where the tools lead the cached prefix, as on Anthropic's API, a helper's first request reads what the session already paid to cache. `LETRONNA_HELPERS_SHARE_TOOLS=off`, or the `helpers_share_tools` setting, sends it every tool as before.
- **All** — A run nobody watches is sent back each time it stops at work still to do, up to three times a run, where it was sent back once and only for a short reply opening "Let me" or "I'll now". After its first tool call, a reply that calls no tool and whose last sentence or clause says what comes next ("Found a bit-order bug — fixing it and re-checking", "Next step: rebuild") is told to continue, and the second time that nothing ran and to call the tool or give its final answer in full. A question, a hand-back to the user and a finished answer are left alone, and when the reply to a send-back is shorter than the one before it, the earlier one stays the run's answer. On Terminal-Bench 2.0 one model ended 19 of its 41 failed runs on such a line. A session someone watches is sent back once, as before.
- **All** — A run nobody watches whose reply writes a tool call out as text, as `<tool_call>` or `<invoke>` markup or as JSON naming one of its tools with arguments, is told that nothing ran and to make the call itself, twice a run at most. Before, the text was the run's answer.
- **All** — After two replies in a row are stopped for thinking without writing, the next is left to finish, and each stop asks for less effort than the last (low, then minimal, then none, as the model offers them). After a second stop in a run, or one past the time warning, the effort stays lowered to the run's end, where it came back with the next reply. On Terminal-Bench 2.0 about thirty stops across nine runs each took a share of the time left, and three in a row left a run's last minutes with nothing written.
- **All** — The warning a run gets at four fifths of its time, and the notice after a reply stopped for thinking, name the files its request names that are not there yet. A run was sent back for those only at its own end, which a run the clock stops never reaches.
- **All** — A run nobody watches that would end with jobs it started still running is sent back once, with the jobs named and how to start one detached if it must stay up, since the run stops its jobs as it ends. A job's start said so already, and on Terminal-Bench 2.0 runs still answered that a server or a virtual machine was up and ended, taking it down.
- **All** — In a run with a deadline, the result of a command that ran for over a minute ends with how long it ran and how much of the run's time is left. Between its start and the warning a run had only its own count: one said it was out of time with 26 minutes to go.
- **All** — A tool call whose arguments arrived empty, to a tool that needs some, is told so once for all of them: that they arrived empty, which are required, and to send the call again. Before, each tool named the one field it looked for first, which reads as a slip in that field.
- **All** — read_job and stop_job take the job as `job` as well as `id`, and wait and send_job as `id` as well as `job`; a command moved to the background says which each takes. Before, `read_job {"job": 3}` failed.
- **All** — The copies of a tester's tests that a run nobody watches put back in its project to run them are deleted as it ends: untracked files that have the file name of a test kept for that run, whose names hold `letronna_spec`. A file git tracks or ignores, one that was there before the tester's were kept, and any other file so named are left alone.
- **All** — A helper that runs out of its token budget makes one more request, with no tools, for its report, which may take it up to a quarter past its limit; a helper at its round cap is asked for its report too. Before, what it had found ended with it. A run whose reviews ran out of budget before reporting is told so, and that this is not a pass.
- **All** — The permission judge waits out a busy provider and asks once more when a gateway drops its request. A call it could not judge is told "not judged", with why and that it may be tried again: that is not a denial.
- **All** — The requirements a run nobody watches is sent back to check have a row for a sentence that opens with a name from code written without backticks, as "get_state_data(state) returns ... None. state_data_values property ..." does: such a paragraph was read as one sentence starting in lower case and left out. "Bail out! ERROR message" is no longer cut at the bang. The check also says that once the run's tests pass, a change of behaviour needs the request's words or a failing row behind it, not a guess at what a test it cannot see might check.

### Fixed
- **All** — A file a command's own redirection made, as `echo draft > notes.txt` makes one, counts as the session's own, as one write_file made does, so a session that has read a page or a document can still write over it or delete it. Before, only files the file tools made counted, and on Terminal-Bench 2.0 a run could not fill in a placeholder in a file it had itself made with `echo`. A file moved onto such a place, or linked there, stays the user's.
- **All** — read_file, write_file and edit_file called without a `path` say that `path` is required. Before, read_file read the project folder in its place and answered "`.` is a folder", which names nothing the call was missing: on Terminal-Bench 2.0 five runs sent it with no arguments again and again until they were stopped for going round in circles.
- **All** — A helper asked to work in a worktree where none can be made, with no project folder, outside a git repository or in one with no commit yet, works in the project folder itself, and the call's answer says so and why. Before, the call was refused, and a model that fills in every field of it asked again the same way: on Terminal-Bench 2.0, whose tasks mostly start outside a repository, three runs were stopped going round in circles on it and the review a run's own check asks for never ran.
- **All** — A command moved to the background at its time limit no longer counts as a build or test that passed. It has no exit code yet, which read as success, so a test suite that never finished stood as the check of the edits before it and the run was not sent back to check them.
- **All** — A reply a gateway breaks off part-way ("The upstream stream ended before the answer finished", a connection reset) is tried again as a failed connection is, within the same limits. Before, a gateway's own wording for it ended the run: on Terminal-Bench 2.0 one failed so with 29 minutes left.
- **All** — Tool calls put together from a stream keep their arguments apart: whole arguments sent a second time are not added to themselves, a `{}` sent ahead of the arguments is replaced by them, arguments that arrive under one call's index while the calls after it have none go to the calls they are for, and a closing copy of a call that carries no arguments leaves what its pieces gathered. A call with no name is noted in the diagnostics where it was dropped in silence.
- **All** — A tester's test command that never got as far as a test, as with a runner not installed or a registry out of reach, is told apart from a failing test: the run is told it says nothing of its work, once, the command gets one more try, and no second attempt is made over it. Before, it read as the work failing its tests.
- **All** — A job a review, a tester or a second attempt left running is stopped as that helper ends, where the run was told of it as a job of its own to start again. The run's file tools reach a tester's test where it is kept, which the run is told to fix there and was then refused.
- **All** — A review of a run nobody watches is read where it writes a verdict with what shows it in the same cell, as `PASS — what shows it`, `FAIL: why`, `PASS (3 cases)` or `the case — PASS` do. Before, only a cell that was the word alone counted: in one benchmark run a finished review wrote all 27 of its rows that way, read as one with no table and was dropped without a word, a failing row with it. A case that merely opens with such a word, as "fails when the input is empty" does, is still no verdict. A review that comes back with no table that can be read at all is now given to the run to read, under a line saying none of its rows is counted, and reviews and testers are asked to write the verdict alone in its cell.

## [0.1.0-alpha.5.1] - 2026-11-11

### Added
- **All** — An MCP server's own tools can act on what that server said, once you list them. `actOnOwnReplies` in a server's entry in `mcp.json` names the tools let past the prompt-injection guard while that server wrote everything the session has read from outside, so a run nobody watches can, say, act on a quote its own server just gave. Read anything else in the session, a web page or another server's reply, and those calls are held as before. Only your own entry can set it, never a plugin's. See docs/extending.md, which says to leave out tools that send money or data to an address.
- **macOS** — `curl -fsSL https://letronna.ai/install.sh | sh` installs Letronna on a Mac: the app in Applications and the terminal on your PATH, then opens it, with no "Apple could not verify" warning to click through. An open Letronna keeps running while its copy is swapped, and one macOS won't let go of is left whole, with what to allow.

### Fixed
- **All** — In the window and the terminal the model finds the tools left out of each request, the scheduler, the browser, helpers and background jobs, when it searches for them. Before, it found none and told you to add a scheduled job by hand.
- **All** — A program a Python plugin starts no longer gets the pipe Letronna's messages come in on, so it can neither read them away nor sit waiting on it. On Windows, `git` started from a plugin's tool, as the git-status and test-gate examples do, no longer hangs.
- **All** — A file a request says to leave unchanged is kept even when its path has a `~` inside a folder's name, such as Windows' short form `C:\Users\RUNNER~1\…`. Only a `~` at the start of a word is read as the home folder.
- **Windows** — The local endpoint ends each reply's connection itself, so a client is no longer left waiting, then reset, when a program started at that moment holds a copy of the connection.

## [0.1.0-alpha.5] - 2026-11-05

### Added
- **All** — A provider takes more than one account: a second ChatGPT or Claude plan, or another OpenAI, Anthropic, Gemini, xAI, OpenRouter or OpenCode Go/Zen key, each named (ChatGPT · Work) and listed under its provider in Settings › Accounts with Add another account, and in `/connect`. When an account reaches its limit, the same model goes on on your next account of that provider first, which Settings › Accounts › When one runs out can turn off, and a full plan is passed over until it resets: "Switched to ChatGPT · Work: ChatGPT reached its limit. It is back at 14:20." The model menu and `/model` list a model once for all of a provider's accounts.
- **All** — Plan usage: each window of a ChatGPT, Claude or OpenCode Go plan (5-hour, weekly, monthly, a model's own) with how much is left and when it resets, from its replies and its own usage page. Settings › Accounts draws a bar for each and Check now asks again; `/limits` lists them in the terminal.
- **All** — OpenCode Go/Zen, one gateway for an OpenCode key: the open coding models of your Go plan go to Go, and every other model OpenCode serves goes to Zen, pay-as-you-go from your OpenCode balance. A key with no Go plan uses Zen alone. Each model goes out in the format its side serves it in (chat completions, Messages, Responses or Google's own), at the address OpenCode gives that format, with the session header OpenCode asks every client for. Every request now names Letronna as its client.
- **All** — Google's own format, `generateContent`: Gemini on OpenCode Go/Zen, which is served in no other, with its thinking shown as it streams and its thought signatures sent back with each tool call, as Gemini 3 requires. A Custom gateway whose base ends in `/v1beta`, such as Google's own API, is spoken to the same way.
- **App** — Settings › Accounts fits on about one screen: the accounts connected come first, one line each with the plan window nearest its limit, and a click opens one in place, shaded and in line with its name, for every window, its key or sign-out, and Use first on the same row as its other buttons. Providers not set up are tiles in a grid as wide as the list, under Add an account, each opening a panel of the same shape, and the fallback order and the local endpoint are folded under More options.
- **Terminal** — `/connect` signs in to ChatGPT or Claude with a code on another device, for a terminal reached over SSH: ChatGPT's own code typed on OpenAI's page, or Claude's page's code pasted back.
- **All** — A paired phone lists this computer's accounts with how much of each plan is left, adds a key or a sign-in, orders them and turns the switch to the next account on or off, over the encrypted link its chats use. Keys only go to the computer; no answer carries one.
- **All** — A plugin can run code with nothing to build: a plugin.json whose `main` is a JavaScript file runs it on Letronna's own engine, sandboxed, and one whose `main` is a Python file runs it on the Python already on the computer. Its code can add tools for the model, look at a tool call before it runs and block it or note on it (never let through what the approval gate stopped), follow turns as they start and end, add slash commands that run code, and keep settings. It runs only once you allow it, you are asked again when an update changes its code, and nothing starts until it is used. See docs/plugins.md, and the guard and git-status examples.
- **App** — A plugin's status shows as a chip in the status bar, its panel as a tab beside the chat drawn with the window's own widgets, and its notices as the window's; its settings are on the Plugins page, and its commands and panel in the command palette.
- **Terminal** — A plugin's status shows in the footer and its notices at the prompt; `/plugins` says what a plugin's code runs and brings, `/plugins settings` and `/plugins set` show and change its settings, and `/plugins reload` starts it afresh.
- **All** — A plugin's code can send the model back when its work is not done (`turn.stop`, as a Stop hook does), add context for the model to read with each message (`prompt.submit`), hear calls that failed (`tool.failed`) and how long each call took, and measure each request's tokens and cost (`model.reply`) and what a whole turn used (`turn.end`). Two more examples: `test-gate` runs your tests when the model says it is done and sends it back until they pass, and `session-meter` shows what each turn used and speaks up when a call keeps failing the same way.
- **All** — Models that run on this computer, with no internet and nothing sent anywhere: Ternary Bonsai 2 (4B, 9B, 27B), Gemma 4 E4B, Qwen3.5 9B, Qwen3.8 27B, Qwen3.6 35B-A3B and Qwen3-Coder-Next, run by llama.cpp's server, which is downloaded with the first one and checked by its hash. Each says before it is downloaded whether it runs well here and about how fast, and the one that suits this computer best is marked. Bonsai 2 4B and 9B may search the web while online; the others chat.
- **All** — When Letronna or another gateway cannot be reached, a downloaded model answers instead and says so ("Switched to Ternary Bonsai 2 · 4B on this computer: Letronna could not be reached"). It can be turned off in Settings › On this computer.
- **App** — Settings › On this computer: what this computer has, every model with its verdict, and Get, a progress ring with Pause, Resume and Cancel, Use, Delete, Show in Finder or Explorer, and photo reading to add or remove. The model menu lists the models downloaded, under On this computer, and first-run setup offers the suggested one.
- **App** — Every model in Settings › On this computer links to the Hugging Face page its file comes from. Add from Hugging Face, under the list, takes a pasted link (a model's page, a file's link, `owner/model` or `owner/model:Q4_K_M`), lists the repository's GGUF files with how each would run here, suggests a 4-bit one, and downloads the one picked, pinned to the commit it was read at and checked by its size and SHA-256 like Letronna's own. A vision file beside it becomes its photo reading. Models added this way chat without web search, are marked "Added from a link", and come off the list when deleted.
- **App** — Each web search shows as a card above the answer, for every model: "Searching the web" while it runs, then "Searched the web · 5 results" with the query, and a click lists the pages, each opening in the browser.
- **Terminal** — A model downloaded to this computer is in `/model`, and `letronna --gateway "This computer" --model bonsai-2-4b` runs one; it says when it is loading, or waiting for another chat.
- **App** — Use this computer from the Letronna app on your phone, encrypted end to end. Messaging › Letronna app pairs a phone with a QR code and six digits to compare, and lists the phones paired. A phone's chats are sessions on this computer, in Default or Plan mode, and each call that needs a yes asks on the phone. Letronna's servers pass the messages on without being able to read them, and nothing on this computer listens on the network. Turn on Over Tailscale there and a phone on the same tailnet pairs and connects straight to this computer instead, which still works when Letronna's servers cannot be reached; only the tailnet address is listened on, port 47821.
- **All** — A commit a session writes ends with `Co-authored-by: Letronna`, and a pull request it writes with Letronna's mark, as Letronna Cloud's sessions already do. Settings › Privacy › Commits and pull requests turns it off for this computer, and, signed in, for Letronna Cloud, which is your account's choice and the same switch as the phone app's.
- **Terminal** — `-p --output stream-json` prints a `step` line as each tool call ends: the tool, what it worked on, whether it worked, and a few lines of what it gave back, or for a change to a file the file, the lines added and taken away and its diff. Letronna Cloud passes these on, so the phone lists a run's steps as it goes.
- **Terminal** — `/local` and `letronna local` list the models that run on this computer, each with how it runs here, how far its download has got and the Hugging Face page it comes from. `get <id>` downloads one, `add <link>` adds one from a Hugging Face link (offering its files to pick from at a keyboard) and downloads it, and `pause`, `resume`, `cancel` and `remove` steer them. In a session a download goes on in the background and says when the model is ready; `letronna local get` and `add` wait for it, showing how far it has got.
- **Terminal** — A `-p --background` run with `--output stream-json` says on its stream when it stops for a yes: an `ask` line with the session, the call, the tool, what it would do and why it asks, and an `answered` line once the answer file is read, so whatever started the run (Letronna Cloud for the phone) can show the question and write the answer.
- **App** — Effort sits at the foot of the model menu (Auto, Low, Med, High, XHigh, Max, as the model has them), and the model's name shows the level only when one is set. `/effort` opens it, and `/effort max`, `/effort extra high` or `/effort auto` sets one straight away. The mode, Crew and Web switches in the chat box show only their icon while at their default and name themselves when on.
- **Terminal** — Alt+P picks the model and Alt+T the effort without losing what is in the box: the draft is set aside while the picker runs and comes back after. Pressed while a reply runs, the picker opens when it ends.
- **All** — A command running in the foreground can be sent to the background and goes on as a job. In the terminal the waiting line ends with `ctrl+b runs it in the background · esc stops it` (`ctrl+b twice` inside tmux), and it works for a `!` line too.
- **All** — A rule kept by "Always allow" can be taken back. `/permissions` in the terminal lists the kept rules, allowed, asked first and denied, each with where it holds, and picking one removes it. Settings › Permissions in the window shows the same rules with a button to remove each.
- **Terminal** — `/tools` switches Letronna's own tool families (Files, Commands, Web, Browser, Media, Messaging, a plugin's) on or off, as the window's Capabilities › Tools page does, with how many of each are off and what each still needs. `/tools on|off <family>` switches one by name.
- **All** — `/redo` puts back what the last `/undo` or `/rewind` took back: the messages, pictures included, and the files as the agent had left them. A file changed since the restore is left alone and named.
- **App** — The terminal's everyday commands work when typed in the window: `/model`, `/mode`, `/plan`, `/compact`, `/rewind`, `/retry`, `/copy`, `/branch` and the rest do what their menus and buttons do, where before they went to the model as text.
- **App** — A line starting with `!` runs as a command in the session's folder, as in the terminal, and its output goes into the chat for the model to see. Esc stops it.
- **App** — Dropping a file or folder on the chat puts it in the box as an `@` reference, so it is attached when sent. A dropped picture is still attached as a picture.
- **App** — Cmd+F (Ctrl+F on Windows), or Find in this chat in the palette, finds words in the open chat, with a count ("2 of 5") and arrows to step between matches.
- **App** — Cmd+= and Cmd+- make the window's text larger or smaller, from 70% to 160%, and Cmd+0 puts it back. The size is kept.
- **All** — A session carries on from the window to the terminal and back. Continue this session in the terminal, in the palette, opens your terminal in its folder running `letronna --resume <id>`, and `/window` in the terminal opens the session on screen in the window.
- **Terminal** — `--name` names the session a run starts or picks up, and `--fork-session` with `--continue` or `--resume <id>` carries on in a copy, leaving the original as it was.
- **Terminal** — `--system-prompt` and `--append-system-prompt` (and their `-file` forms) replace Letronna's own instructions with yours, or add yours after them, for that run. The project's instructions, skills and tool rules are kept either way.
- **Terminal** — `/terminal-setup` names the terminal you are in, says which keys make a new line there, and gives the exact setting for Shift+Enter and Option or Alt where they do not work yet.
- **Terminal** — Ctrl+Z hands the screen back to the shell, and `fg` brings the session back as it was.
- **Terminal** — While a turn runs, terminals that draw progress in the tab (Windows Terminal, ConEmu, Ghostty, iTerm2) show a running bar there.
- **Terminal** — A copy says so with a green check and how much was taken ("copied 35 characters"), then the footer comes back after four seconds. Ctrl+V takes any picture on the clipboard, such as one copied in Preview or Safari, and a file copied in Finder.
- **Terminal** — The queued line says how to send it now or take it back (`ctrl+s sends now · ↑ edits it`), and `/help` and the `?` card list every key the box answers to, Ctrl+R and Ctrl+L included.
- **Terminal** — `/vim` gives the box vim's keys: normal and insert mode shown in the footer, motions, `d c y` with counts, text objects, `p`, `J` and `u`.
- **Terminal** — `/theme` picks the terminal's colours, with themes for dark and light backgrounds and ones that tell an added line from a removed one by more than red and green. The default looks as it did, and the choice is kept.
- **Terminal** — `/statusline <command>` shows your own status line under the footer. The command is handed the session as JSON in the same shape as Claude Code's `statusLine`, so a script written for it works here.
- **Terminal** — Keys can be moved in `keybindings.json`, which `/keybindings` opens: each key maps to an action, a `/command`, or nothing to unbind it.
- **All** — A recap of where a session stands, in two or three short lines: what was asked, what was done and what is left. `/recap` asks for one in the terminal and the window, and a session picked up more than 30 minutes after its last reply gets one unasked.
- **All** — More hooks in hooks.json run: `PostToolUseFailure` after a call that failed, `SubagentStop` when a helper finishes, `PreCompact` before a session is summarized, and `SessionStart` and `UserPromptSubmit` at a turn's start, which can add context or turn a prompt back. `/hooks` in the terminal lists the hooks the file holds.
- **All** — A project can have its own formatter run on every file the model writes (rustfmt, prettier, black, gofmt and others, as the project sets up), so edits come out in the project's layout. `/format` in the terminal and "Format edits in this project" in Settings › Thinking switch it on.

- **All** — `/review` takes a GitHub pull request by its number or link, fetching it without touching your checkout, and posts nothing to it without a yes.
- **Terminal** — `letronna --bg "task"` works on with the terminal closed, and `/background` sends the session there. `letronna attach <id>` watches it and answers what it asks, and `letronna stop <id>` ends it. The window sends nothing into a session working in the background and says how to reach it.

- **All** — A run nobody may be watching, such as `letronna -p`, a schedule or a chat app's, drops a reply with no tool call that goes round on the same few words for 2,000 characters or more, writing almost no line or sentence in its later half it had not written already, or that is still empty after it was asked once to say something, and sends the same request again after a rest of 2, 4 and then 8 seconds, three times a round at most, rather than taking the filler as its answer, carrying it in every later request, or ending on the empty reply. - **All** — A run nobody watches, such as `letronna -p`, that ends with a path its request names still not there, such as `src/run.js` or `/srv/app/report.pdf`, is sent back once to weigh it against the request, in the same check that names a missing output under `out/`, unless it can neither write files nor run commands. Only one written with its folder counts, not a name alone; not one in an example, in code or a diff, a placeholder, such as `<name>` or `YYYY-MM-DD`, a URL, or one with a line or port after it, such as `src/app.js:42`; not what a command the request shows writes, such as the file after `-o` or `>`; nor one in a sentence about reading, removing or moving files, or saying not to make it, to make it later or that it is optional or not needed.
- **All** — On a run given `LETRONNA_DEADLINE`, the reply in place of one stopped for thinking without writing anything goes on from that thinking, which comes with the notice to write now, trimmed to its start and end when long; the reply asks for low effort, or the nearest the model offers, never more than the run was set to, and the run's own effort comes back with the next reply. - **All** — On a run with a deadline, such as `letronna -p` given `LETRONNA_DEADLINE`, a command given longer than the default two minutes carries on in the background, with its output so far, once it has had half of the time left, and two minutes at least, or once past two minutes as soon as a notice such as a background job's exit is waiting, so the model hears it now rather than after the command's own limit.
